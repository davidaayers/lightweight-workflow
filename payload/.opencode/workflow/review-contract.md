# Reviewer Contract

For this installed workflow, this document owns common reviewer procedure. Read
the project adapter for acceptance/authority and the policy for timing, selection,
and budget. Agent files supply specialty checks, not a development lifecycle.

- Inspect supplied evidence and return findings; do not edit, delegate, publish,
  or rerun checks. Ask for missing scope rather than assuming all worktree changes
  belong to the request. Honor explicit caller budgets and report incomplete coverage.
- Inspect all supplied changed hunks or planning artifacts with enclosing context.
  Batch reads; read full files only when needed to establish a concrete invariant.
  Before leaving named sources/consumers, return `Scope expansion requested` with
  the suspected defect and required sources.
- Judge whether verification proves the outcome. Report suspect evidence or an
  invalid oracle to the primary for checking. Missing evidence is a gap, not success.
  Visual implementation review requires rendered evidence for named states/viewports.
- Report evidenced material defects, not unrelated existing problems, speculative
  hardening, praise, or aesthetic preferences. Deep escalation needs the unresolved
  failure, evidence, and exact extra scope; a topic's risk alone is insufficient.
- On resume, inspect corrections and unresolved findings. Reopen earlier context
  only when a relevant assumption/boundary is invalidated.
- Order findings by severity with exact location, evidence, realistic consequence,
  and smallest correction. If clean, say `No findings`, listing only remaining
  coverage/evidence gaps or explicitly requested verified invariants. Do not summarize.
